# 质量修复与微信公众号评估

## 已修改

- AI最多每批6条；短ID A01/A02；逐条校验并保留成功结果，仅失败条目重试一次。最终仍失败的条目accepted=false、score=0，保留候选数据库但不推送。旧评分缓存通过版本签名隔离。
- 模型响应结束原因、累计Token用量及校验错误码进入日志。不保存模型原文、密钥或请求头。异常退出也写用量日志。
- 有效中文摘要≤50字不调用AI；长摘要或英文摘要仅传摘要做压缩/翻译；无效摘要改用正文；生成不合格不硬切数字、不填垃圾摘要，暂不推送。新摘要缓存30天清理。
- 中文短摘要最低12字符/6个汉字是初始质量门槛，可后续根据真实反馈调整；并不保证所有合格文本都忠实，仍需真实样本验收。
- 短摘要HTML卡片有限补读正文；增加脑机公司/脑机企业/脑机耳机同义表达。
- 东方财富财经入口启用，日期适配 `.infos > .item`；原文链接及转载来源保留，排除股吧/概念股等规则不变。
- DeepMind因未确认足够直接的相关内容暂停常规采集；国家药监局仍用原有官方域名搜索，直读412不绕过；Bing RSS仍关闭。

## 用户指定Skill的评估

仓库：https://github.com/oldjie/wechat-article-parser

已完整阅读 SKILL.md、README介绍、scripts/fetch-wechat.js、MIT许可。未全局安装或执行原脚本。

原脚本使用Node.js + Playwright/Chromium + Cheerio：输入一篇已知微信URL，加载浏览器，等待正文后提取 `#activity-name`、`#js_name`、`#publish_time`、`#js_content`。它不含公众号搜索、历史列表、定时发现功能；域名判断只用字符串包含，也不足以直接用于无人值守服务。

我们借鉴其字段选择器，加入Python轻量文本适配、精确域名/路径验证、正文空值检测、时间戳静态提取，不下载图片，不复用登录Cookie，不执行网页脚本。MIT许可保留在 wechat-article-parser-LICENSE.txt。

已知链接接入点：config/wechat.yaml 的 article_urls；现有搜索发现的微信链接也能进入文章详情解析器。没有新加公众号付费搜索调用。未使用Omni/mptext渠道，不再需要WECHAT_AUTH_KEY。

本机对上游README示例URL进行公开读取测试，Reader返回robots禁止抓取。因此没有把代码接入等同于真实可用：wechat_enabled仍为false。未安装浏览器，未测试原版Playwright脚本。即使浏览器能读取某一篇，也仍然不能解决自动发现文章的问题。

如后续使用用户提供的有权访问的正文或授权RSS，可以保留现有去重、日期、相关性和50字摘要流程。不能承诺无需凭证即可稳定自动采集所有公众号。
